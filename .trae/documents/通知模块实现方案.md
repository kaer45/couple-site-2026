# 通知模块实现方案（站内信：列表 / 未读 / 已读）

## Context（背景）

纪念日提醒任务已经实现：`AnniversaryReminderServiceImpl` 会往 `notification` 表写入站内信（按情侣内每个成员各插一条，`user_id` 唯一）。但目前**没有任何读取/消费这些通知的地方**——用户看不到提醒。

本次增加通知的读取侧：分页列表、未读数红点、标记已读、全部已读，并在前端顶部栏加铃铛入口。核心是按**当前登录用户**（`CoupleUserPrincipal.id()`）过滤，因为通知是按 `user_id` 存、且读取与情侣绑定 `coupleId` 无关。

已确认的交互决策：铃铛下拉面板（含"查看全部"）+ 独立通知页 `/notifications`（加载更多分页）+ 进入页面时拉取未读数 + 单条仅标记已读不跳转。

---

## 后端

沿用现有约定：`Result` 包裹、`PageResult` 分页、`@AuthenticationPrincipal CoupleUserPrincipal` 取当前用户、MyBatis-Plus `LambdaQueryWrapper`/`LambdaUpdateWrapper`、`BusinessException(404)` 表示不存在。

现有类**不移动**：`Notification`(entity)、`NotificationMapper`、`NotificationService`(+Impl) 已位于 `com.couple.anniversary` 包，为最小改动继续留在此包（提醒逻辑的 import 不变）。

### 新增/修改文件

1. **新增 `com.couple.anniversary.dto.NotificationVO`**：`id, type, title, content, isRead, createdAt`（不含内部字段 userId/coupleId/relatedId）。由 entity 构造。

2. **扩展 `NotificationService`**（接口 + `NotificationServiceImpl`），新增 4 个方法：
   - `PageResult<NotificationVO> page(Long userId, long current, long size)`：`new Page<>(current,size)` + `eq(userId)` + `orderByDesc(createdAt)` → `PageResult.of(page, records映射VO)`。复用 [PageResult.java](file:///d:/project/dsh/couple-site/backend/src/main/java/com/couple/common/PageResult.java)。
   - `long unreadCount(Long userId)`：`selectCount(eq userId, eq isRead false)`。
   - `void markRead(Long userId, Long id)`：update `eq id + eq userId` set isRead=true；受影响行数 0 → 抛 `BusinessException(404, "通知不存在")`。
   - `int readAll(Long userId)`：update `eq userId + eq isRead false` set isRead=true，返回条数。

3. **新增 `com.couple.anniversary.controller.NotificationController`**，`@RequestMapping("/api/notifications")`：
   - `GET /api/notifications` → `Result<PageResult<NotificationVO>>`，参数 `current`(默认1)、`size`(默认10)。
   - `GET /api/notifications/unread-count` → `Result<Long>`（**注意：此路径在 Spring 中与任何 `{id}` 无冲突**）。
   - `PUT /api/notifications/{id}/read` → `Result<Void>`。
   - `PUT /api/notifications/read-all` → `Result<Void>`。

> 注：后端无需 `@EnableScheduling` 改动（已开启）。

## 前端

Element Plus 已全量引入（`el-badge`、`el-popover`、`el-empty` 可用）；已有 `dayjs` + `relativeTime`（中文）；请求走统一 `request`（已注入 token、`code===0` 才返回 data）。

### 新增/修改文件

1. **新增 `frontend/src/api/notification.js`**：`page({current,size})`、`unreadCount()`、`markRead(id)`、`readAll()`。

2. **新增 `frontend/src/stores/notification.js`**（Pinia）：共享状态 `unread`，方法 `refresh()`（拉未读数）、`decrement()`（本地 -1，下限0）、`reset()`（登出清零）。避免 Layout 与通知页重复逻辑。

3. **改 `frontend/src/layout/Layout.vue`**：
   - header-right 加一个铃铛：`el-popover` + `el-badge`（`value=unread`，为 0 时 `:hidden`）。铃铛用全局图标 `<Bell />`。
   - Popover 内：最近 5 条（打开时 `page({current:1,size:5})`），每条显示标题、`dayjs(createdAt).fromNow()`、未读圆点，点击 → `markRead(id)` + `store.decrement()`。底部"查看全部"按钮 → `router.push('/notifications')`。
   - `onMounted` 调 `store.refresh()`。（当前已有一个 onMounted 拉用户信息，合并调用。）
   - 退出登录时调 `store.reset()`。

4. **改 `frontend/src/router/index.js`**：在 Layout children 下加 `path:'notifications'`，name `notifications`，title `通知`，`requiresAuth: true`。

5. **新增 `frontend/src/views/Notification.vue`**：
   - 载入加载第 1 页（size 10），时间倒序；空态用 `EmptyState`。
   - 每条渲染标题、内容、相对时间、未读样式（未读加粗/圆点、已读弱化）；点击 → `markRead` + 本地标记已读 + `store.decrement()`。
   - 顶部"全部已读"按钮 → `readAll()` + 刷新未读数。
   - 底部若有 `hasMore` 显示"加载更多"按钮，append 下一页。

> 左侧菜单不加通知入口（铃铛 dropdown 的"查看全部"即入口）。

## 验证（端到端）

1. 后端：`cd backend && mvn spring-boot:run`。
2. 造数据：用现有纪念日 + `/api/test/remind/trigger` 生成通知；若当天无恰好的提醒，**用 SQL 手动向 `notification` 直插 2~3 行**（含 `user_id` 对应当前登录用户、部分 `is_read=0`）。
3. 领取 token：登录一位用户，取 `Authorization: Bearer ...`。
4. 逐一验证 curl（或前端操作）：
   - `GET /api/notifications?current=1&size=10` 返回本人分页数据。
   - `GET /api/notifications/unread-count` 未读数正确。
   - `PUT /api/notifications/{id}/read` 后 unread-count -1；再调同 id → 理想情况 404或已读幂等。
   - `PUT /api/notifications/read-all` 后 unread-count=0，列表全已读。
   - 越权：用 A 用户改 B 的通知 → 404。
5. 前端：`cd frontend && npm run dev`，检查顶部铃铛红点数量、点开面板最近 5 条、点击单条未读消失、点"查看全部"跳转、通知页加载更多/全部已读、登出后回登录页。
