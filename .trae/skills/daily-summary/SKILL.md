# 每日总结生成器

将当天的工作内容整理成一份结构清晰、简洁干练的每日总结。

## 何时使用

当用户出现以下意图时，启用本技能：
- 说"帮我总结今天"、"生成每日总结"、"今日复盘"、"总结一下今天"
- 把当天的笔记、记录（md 文件、对话内容）发给你，并要求整理成总结
- 提到"回顾今天"、"今天做了什么"

## 信息来源

优先合并以下两类来源，去重后整理：
1. **用户在日期目录下已写的 md 文件**：先读取 `D:\project\dsh\couple-site\couple-site-self-learning-docs\YYYY-MM-DD\` 目录下用户自己写的 md
   - 0 个：跳过此来源
   - 1 个：直接读取
   - 多个：询问用户要读取哪一个
2. **今日对话历史**：回顾今天用户提出的问题和我们的交流内容

如果两类来源都有，合并去重；如果只有一类，就用那一类。

## 目录结构

所有文件存放在按日期命名的目录下：

```
D:\project\dsh\couple-site\couple-site-self-learning-docs\
└── YYYY-MM-DD\
    ├── daily.md              ← 每日总结（本技能生成）
    ├── {主题1}.md            ← 学习笔记（learning-note 生成）
    ├── {主题2}.md
    └── 用户自己写的笔记.md    ← 用户提前写的，本技能先读取
```

每日总结保存为：`D:\project\dsh\couple-site\couple-site-self-learning-docs\YYYY-MM-DD\daily.md`

## 处理步骤

1. **确定日期目录**：当天日期 `YYYY-MM-DD`，拼接路径 `D:\project\dsh\couple-site\couple-site-self-learning-docs\YYYY-MM-DD\`
2. **读取用户笔记**：检查该目录下已有的 md 文件（排除 `daily.md` 和可能已存在的学习笔记），按数量处理（0 个跳过、1 个读取、多个询问）
3. **回顾对话**：回顾今日对话历史
4. **提取**：从来源中提取——完成的事项、做出的决策、未完成的待办、遗留的问题
5. **识别学习重点**：找出用户着重学习的部分（用户明确说"要学"、"重点"、或花较多篇幅讨论的技术/业务点）
6. **生成学习笔记**：对每个学习重点，调用 `learning-note` 技能生成 `{主题}.md`，保存到同一日期目录
7. **归类**：按主题/模块归类，合并重复项
8. **输出并保存**：按下文格式生成总结，学习重点处用链接引用对应的学习笔记（同目录，直接写文件名），然后保存为 `daily.md` 到该日期目录

## 输出格式

```markdown
# 📝 每日总结 — YYYY-MM-DD

## ✅ 今日完成
- 事项一（模块/主题）
- 事项二

## 📚 深度学习
- 学习了 {主题}，详见 [学习笔记]({主题}.md)
- （如果当天没有学习重点，此段省略）

## 🤔 关键决策
- 决策内容（简要背景）

## 📋 待办 / 跟进
- [ ] 待办事项一
- [ ] 待办事项二

## ❓ 未解决问题
- 问题一

## 📌 明日重点
- 重点一
- 重点二

## 💡 收获与反思
- 收获或踩坑记录
```

## 写作规则

- **简洁干练**：每条不超过 2 行，用列表呈现，避免长段落
- **只写真实内容**：只记录来源中实际出现的事项，不编造、不脑补
- **空段省略**：某段没有内容时直接省略该段，不要写"无"
- **重点可详写**：对于用户明确强调的重点、或用户掌握不好的部分，可以比其他条目多写 1-2 句上下文说明
- **用用户的语言**：保留来源中的关键术语和项目名，不随意改写
- **明日重点**：基于今日未完成事项和进展推演 1-3 条，不要列太多

## 注意事项

- 不要输出分析过程，直接给出最终总结
- 日期使用当天日期（YYYY-MM-DD 格式）
- 如果来源内容很少，如实呈现，不要凑内容
